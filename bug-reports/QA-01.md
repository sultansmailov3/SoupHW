# QA-01 — Duplicate training.epochs is silently overwritten

**Environment.** Soup CLI 0.77.2, Google Colab Tesla T4, Python and dependency versions in the accompanying logs.

**Minimal reproduction.** In `configs/baseline.yaml`, replace the single indented `epochs: 1` with two lines at the same indentation, first `epochs: 1`, then `epochs: 2`. Copy the dataset next to the config and run `HF_HUB_OFFLINE=1 soup plan -c soup.yaml`. Run `python -m pytest -q -rx -k duplicate_epochs` to record both the CLI exit and the effective value.

**Expected.** Reject the ambiguous YAML before planning or training and identify the duplicated key.

**Actual.** Planning exits 0, writes `soup.tfstate`, and gives no duplicate-key warning. The effective value is 2. See `logs/cases/duplicate-plan-*/` and `logs/cases/duplicate-effective-*/`.

**Severity.** Medium. An accidental duplicate can override the intended amount of training and alter the output.

**Training confirmation.** The clean training run recorded 4 steps and status completed; the duplicate-key run recorded 8 steps and status completed. Both use the same data and starting model. Hugging Face trainer checkpoints independently record 4 versus 8 steps. Evidence: `logs/training-20261111T204021725344Z/comparison.json`.
